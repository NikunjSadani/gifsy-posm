# POSM Go-Live — Owner Checklist

The build is complete and runtime-proven locally. Everything below is **owner-gated** — I can't do it
(it needs your accounts/decisions). I hand you exact commands; you run them. Once these clear, the deploy
itself is ~3–5 working days of my work. Order matters top-to-bottom.

Canonical detail: `DEPLOYMENT-PLAN.md` (§3 blockers, §5 decisions), `terraform/README.md` (apply flow),
`DEPLOY-CONTRACT.md` (names), `DEPLOY-ENV-VARS.md` (env inventory).

---

## Step 0 — Decisions (nothing can start until these are made)

- [ ] **D1 — Production DB placement (THE #1 call).** Where does `posm_prod` live?
  - `gifsy-shared` instance (cheapest; shared blast radius — and it **doesn't exist yet**), OR
  - a **dedicated `posm-prod` instance** (own failure domain; recommended for a paying client), OR
  - a **dedicated GCP project** (strongest isolation).
  - → sets Terraform `sql_instance` + `create_sql_instance`.
- [ ] **D2 — Domain.** `posm.gifsy.in` vs a Kwality-facing domain. (Staging can be `uat-posm.gifsy.in`.)
- [ ] **D3 — Warm prod?** Cloud Run min instances `0` (cheaper, ~cold-start delay) vs `1` (warm, costs more).

## Step 1 — GitHub (the repo is currently LOCAL-ONLY — nothing is pushed anywhere)

- [ ] Create a **private** GitHub repo (e.g. `NikunjSadani/gifsy-posm`).
- [ ] Tell me the `owner/name`; I add the remote and push `develop` + `main`.
- [ ] ⚠️ Confirm **GitHub Actions billing / spending limit** is healthy and set a limit — your other repos
      hit a spending-limit block that silently fails deploys. Fix this now or the first CI deploy blocks.

## Step 2 — GCP project (billing is the long pole)

- [ ] Create / choose the GCP project (per D1) and **enable billing**.
- [ ] Grant yourself Owner (or the admin roles listed in `terraform/README.md` Prerequisites).
- [ ] `gcloud auth login` locally.

## Step 3 — Bootstrap (run my script — the only by-hand GCP prep)

```bash
PROJECT_ID=<your-project> STATE_BUCKET=<your-project>-tfstate ./scripts/bootstrap-gcp.sh
# add SQL_INSTANCE=<name> if you chose a shared/pre-existing instance (D1)
```

This enables core APIs + creates the Terraform state bucket. (Cloud Run, Cloud SQL DB/user, GCS media
buckets, Secret Manager, IAM, WIF, Artifact Registry are all created by Terraform next — my job.)

## Step 4 — Secrets you must supply (I wire them; I never invent them)

- [ ] **MSG91 SMTP** credentials for email reports + ASM reminders:
      `posm-<env>-msg91-smtp-user`, `posm-<env>-msg91-smtp-pass` (and MSG91 auth key / OTP template if used).
      Without these, scheduled emails + ASM reminders won't send (everything else works).
- [ ] (DB password + JWT secret are auto-generated by Terraform — you don't supply these.)

## Step 5 — Cloud SQL (only if you chose shared, D1)

- [ ] If using a shared instance that doesn't exist yet (`gifsy-shared`), create it first, or switch D1 to
      dedicated. `bootstrap-gcp.sh` with `SQL_INSTANCE=` will tell you whether it exists.

## Step 6 — DNS (after staging is up)

- [ ] Point the chosen domain(s) (D2) at the Cloud Run frontend / edge once I give you the target.

## What happens after (my work — Wave B, ~3–5 days)

you** (the real "done" bar).
